# 락 멈춤 측정 결과

한 Store에 키 1,000,000개를 넣고, 다른 스레드가 `key:0`를 계속 get하는 동안 메인 스레드가 O(N) 작업을 한다.
"최대 대기"는 작업 구간과 겹친 그 get들(끝 >= 작업 시작, 시작 <= 작업 끝)의 지연이다.
겹친 요청이 하나도 없으면 호출 수는 0이고 지연 칸은 "겹친 요청 없음"이다.
Store 단계의 측정이다. HTTP는 자기 오버헤드를 더하고, GIL 넘겨받기 비용은 대조 B가 보여 준다.
`python -m bench.lock_pause`가 이 파일을 다시 만든다.

- 기계: Windows-11-10.0.26200-SP0, Intel64 Family 6 Model 197 Stepping 2, GenuineIntel, CPU 14개, Python 3.14.7
- 키 수 N: 1,000,000 (prefix 행은 `user:` 키 100,000개 = 비율 0.1, 나머지는 `key:`)
- 반복: 행을 번갈아 3번, 반복마다 한 줄씩 그대로 적는다
- GC: 끔
- sys.getswitchinterval(): 0.005초

## GET이 같이 옮겨 주는 리해싱, 두 스레드

리사이즈 두 행은 GET이 같이 옮겨 주는 리해싱, 두 스레드이다. 희생자의 GET도 버킷을 옮기므로 점진적 행의 리해싱은 두 스레드가 나눠 한다.
이 행들의 처음 크기는 N과 다르다. 마지막 리사이즈 문턱 바로 아래까지만 채운 Store에서 시작해, 새 키를 넣어 리사이즈가 끝날 때까지 가기 때문이다.
