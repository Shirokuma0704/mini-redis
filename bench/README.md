# 성능 측정 스크립트 (Perf 이슈에서 추가)

## 만료 회수: 타이밍 휠 vs lazy만 (#21)

레포 루트에서 돌린다(키 10만 개 기본값으로 약 4초).

```bash
python -m bench.expiry_reclaim
```

```bash
python -m bench.expiry_reclaim --keys 1000000 --seconds 120
```

[results/expiry_reclaim.csv](results/expiry_reclaim.csv)(1초마다 남은 만료 키 수)와 [results/expiry_reclaim.md](results/expiry_reclaim.md)(요약 표와 그래프)를 다시 만든다.
`python bench/expiry_reclaim.py`로 부르면 설치된 다른 체크아웃의 `mini_redis`를 읽을 수 있어서 `-m`으로 부른다.

### 무엇을 재나

키 N개를 t=0에 저장하고, 같은 키와 같은 읽기 순서(시드 21)로 두 번 돌린다.

- **휠**: 100ms마다 `Store.expire_tick()`을 부른다(만료 스레드가 하는 일과 같다).
- **lazy만**: tick을 부르지 않는다. 읽힌 키만 `_get_live`가 지운다.

두 방식 모두 핫 키 10%에만 tick마다 EXISTS 100번을 보낸다. 1초마다 tick 직전에 `store.size() - 살아 있는 키 수`, 곧 "만료됐는데 아직 메모리에 남은 키 수"를 센다.

| 시나리오 | TTL |
| --- | --- |
| spread | 1~60초에 고르게 |
| burst | 전부 10초 (tick 상한 1,000개에 걸리게) |

### 결과 (키 10만 개, 70초)

| 시나리오 | 방식 | 최대 | 평균 | 끝(70초) |
| --- | --- | ---: | ---: | ---: |
| spread | lazy만 | 91,690 | 52,803 | 90,606 |
| spread | 휠 | 196 | 144 | 0 |
| burst | lazy만 | 99,901 | 79,919 | 90,028 |
| burst | 휠 | 99,901 | 7,369 | 0 |

- **spread**: lazy만 쓰면 읽히지 않는 90%가 그대로 쌓여 70초에 90,606개가 남는다. 휠은 언제 재도 최근 100ms 안에 만료된 키(140~196개)만 남고, 마지막 만료(60초) 뒤에는 0이다.
- **burst**: 10초에 99,901개가 한꺼번에 만료된다. 휠은 tick당 1,000개 상한 때문에 1초에 1만 개씩 지워 20초에 0이 된다. lazy만은 70초에도 90,028개가 남는다.
- **tick 소요 시간**: 1,000개를 지우는 tick은 약 2ms다. 결과 파일의 tick 최대(이 컴퓨터에서 spread 약 12ms, burst는 실행마다 25~80ms)는 2단 슬롯을 1단으로 내려보내는 tick에서 나온다. burst는 10만 개를 한 tick에 옮기면서 락을 수십 ms 잡는다. tick당 상한은 삭제에만 걸리고 내려보내기에는 걸리지 않는다.

그래프는 [results/expiry_reclaim.md](results/expiry_reclaim.md)에 있다.

### 왜 가짜 시계인가

만료 스레드는 100ms마다 `expire_tick()`을 부를 뿐이고, 무엇을 지울지는 주입한 시계 값으로 정해진다. 그래서 가짜 시계로 같은 호출 순서를 재현하면 결과가 결정적이고, 70초 측정 네 번이 몇 초면 끝난다.

실제 시간에서만 생기는 차이는 tick 자체가 걸리는 시간만큼 주기가 늘어나는 것과 스레드 스케줄링 지연이다. 실제 만료 스레드(`start_expiry`)로 2만 개 burst를 한 번 돌려 보니 만료 뒤 약 2.3초에 비워졌다. 가짜 시계 예측(2.0초)에 tick 올림(최대 100ms)과 스레드 위상을 더한 정도다.

### 한계

- 요청 스레드와 만료 스레드가 락을 두고 다투는 상황은 없다. 읽기도 같은 스레드에서 순서대로 한다.
- 휠 쪽은 tick 직전에 재므로 최근 100ms 동안 만료된 키까지 남은 것으로 센다(휠에 불리한 쪽).
- tick 상한 때문에 한꺼번에 만료되는 키가 많으면 휠도 1초에 1만 개씩만 지운다. 키 상한 100만 개가 동시에 만료되면 다 비우는 데 100초다.
- 키 수만 재고 메모리 바이트는 재지 않는다.
- TTL이 60초 안이라 overflow 힙(약 6.8분 넘는 만료)은 거치지 않는다.
