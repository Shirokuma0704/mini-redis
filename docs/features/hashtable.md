# 해시테이블

## 개요
키-값 저장의 바닥 계층이다. Python `dict`를 쓰지 않고 체이닝 해시테이블을 직접 구현해, 평균 O(1)로 조회·삽입·삭제한다. 락은 잡지 않으며 `Store`가 전역 RLock으로 보호한다.

## 사용 기술
- **체이닝(연결 리스트)**: 같은 버킷에 충돌한 엔트리를 `next`로 이어 붙인다. 오픈 어드레싱보다 삭제가 단순하다(체인에서 떼어내기만 하면 됨).
- **FNV-1a 64비트**: 바이트마다 `XOR` 후 소수를 곱하는 간단한 해시. Python 내장 `hash()`는 프로세스마다 값이 달라(해시 시드) AOF·스냅샷 재현성과 테스트에 맞지 않아 쓰지 않는다.
- **2의 거듭제곱 capacity**: 나머지 연산 대신 `hash & (capacity - 1)`로 버킷 번호를 구한다. 초기 16.
- **일괄 리사이즈**: `size / capacity > 0.75`이면 배열을 2배로 만들고 모든 엔트리를 한 번에 재배치한다. 축소는 하지 않는다. 대안인 점진적 리해싱(Redis 방식)은 스트레치(#24)로 둔다.

## 동작 흐름
1. `put(key, value, expire_at_ms)`: `fnv1a_64(key) & (capacity-1)`로 버킷을 정한다.
2. 체인을 돌며 같은 키가 있으면 값과 만료 시각을 교체하고 `False`를 반환한다.
3. 없으면 체인 **머리**에 새 엔트리를 삽입하고 `size`를 올린다(`True`).
4. 삽입 후 load factor가 0.75를 넘으면 `_resize()`가 새 배열(2배)에 모든 엔트리를 다시 해시해 옮긴다.
5. `get(key)`: 같은 방식으로 버킷을 찾아 체인을 비교하며 엔트리를 반환, 없으면 `None`.
6. `delete(key)`: 체인에서 이전 노드의 `next`를 이어 붙여 제거(처음·중간·끝 모두 처리).
7. `items()`: 모든 버킷을 순회해 엔트리를 내보낸다. 다음 노드를 미리 저장해 순회 중 삭제에도 안전하다. KEYS, prefix 삭제, 스냅샷이 사용한다.

## 엣지 케이스와 한계
- 충돌이 몰리면 최악 O(n). 테스트는 `hash_fn` 주입으로 충돌을 강제해 체인 처음·중간·끝 삭제를 검증한다.
- 리사이즈는 O(n)이고 Store 락을 잡은 채 일어나 그 순간 모든 요청이 멈춘다. 성능 테스트(#20)에서 측정한다.
- 만료 판단은 이 계층이 하지 않는다. `expire_at_ms`는 저장만 하고 Store가 해석한다.
- 새 키 삽입 여부를 `put`의 반환값으로 알려 Store가 키 상한(507)을 검사할 수 있게 한다.
